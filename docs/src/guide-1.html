How to use this

This is written to be read in order, and it assumes nothing. Part I starts at what a model is. If you already know that machine learning is curve fitting and that a transformer predicts the next token, skip to Part III. If you want only the project, start at Part VII, though it will make more sense with Part IV behind you.

Three kinds of box appear throughout. A definition box gives you a term you will meet again. A plain English box restates something technical the way you would say it out loud to a colleague. A caution box marks a place where the common understanding is wrong, or where this project got something wrong and had to fix it.

Every number in this guide about the project comes from a real run of 738 trials that cost $11.02 and is stored in the repository. Every company figure was checked against a primary source. Where something is uncertain, it says so.

Part I · Machine learning from zero

Chapter 1What a model actually is

Strip away the vocabulary and a machine learning model is a function: something that takes an input and returns an output. You already know functions. f(x) = 2x + 1 is a function. Give it 3, it returns 7.

The difference is where the numbers come from. In f(x) = 2x + 1, a human chose the 2 and the 1. In a machine learning model, nobody chooses them. The model starts with random numbers and adjusts them until its outputs match examples it was shown. Those adjustable numbers are called parameters, or sometimes weights.

Definition · Parameters

The adjustable numbers inside a model. GPT-3 had 175 billion of them. Modern frontier models do not publish the figure. A parameter is not a fact or a rule; it is one number in an enormous arithmetic expression, and no single one means anything on its own.

So: a model is a function with a very large number of tunable knobs, and training is the process of turning those knobs. That framing carries you surprisingly far. When someone says a model "learned" something, what physically happened is that some numbers changed.

Consider a concrete, small example. You want to predict a house price from its size in square metres. You collect 500 houses with known sizes and prices. You propose price = a × size + b. You do not know a or b, so you start with a = 0 and b = 0, which predicts every house costs nothing. That is a terrible model. Training is the procedure that walks a and b from terrible to good.

Chapter 2How training actually works

Training needs three things: a way to measure wrongness, a way to know which direction reduces it, and a rule for how big a step to take.

The loss function

Wrongness is measured by a loss function. The simplest is squared error: for each house, take the predicted price minus the real price, square it, and average across all houses. Squaring does two jobs. It makes errors positive, so being 50,000 over and 50,000 under does not cancel to zero. And it punishes large errors far more than small ones, because 100 squared is 10,000 while 10 squared is only 100.

Definition · Loss

A single number saying how wrong the model currently is across the training examples. Lower is better. Training is, mechanically, the search for parameters that make this number small.

Gradient descent

Now you need to know which way to turn the knobs. This is where calculus enters, and the intuition matters more than the mathematics.

Imagine you are standing on a hillside in thick fog and want to reach the valley floor. You cannot see the valley. But you can feel the slope under your feet. So you take a step in whichever direction goes down most steeply, then feel again, then step again. Repeat enough times and you arrive at a low point.

That is gradient descent. The "hillside" is the loss as a function of the parameters. The "slope" is the gradient, which is what the derivative gives you: for each parameter, which way and how steeply the loss changes if you nudge it. The step size is called the learning rate. Too large and you bound over the valley to the opposite slope; too small and you take a million years to descend.

Plain English

Training a model is: guess, measure how wrong you are, work out which direction is less wrong, take a small step that way, and repeat several million times.

Backpropagation

With two parameters, computing the gradient is easy. With billions, arranged in layers where each one feeds the next, you need an efficient way to attribute the final error back to every individual parameter. That algorithm is backpropagation, published in its influential form by Rumelhart, Hinton and Williams in 1986.

Backpropagation applies the chain rule from calculus, working backwards from the output. It answers, for every parameter in the network, "if this one number changed slightly, how much would the final error change?" It is not conceptually deep. It is an accounting method, and its importance is that it is fast enough to be practical.

Chapter 3Neural networks

A straight line cannot describe most real relationships. House price does not rise linearly with size forever. Neural networks exist to represent complicated, curved, interacting relationships without you having to specify their shape in advance.

The building block is a neuron, and it is embarrassingly simple. It takes several numbers in, multiplies each by a weight, adds them up, adds a constant, and passes the result through a small non-linear function. That is it.

output = activation( w1·x1 + w2·x2 + w3·x3 + bias )

The activation function is the load-bearing part. The most common is ReLU: if the number is negative, return zero; otherwise return it unchanged. Absurdly simple, and it is what allows networks to represent curves. Without a non-linear activation, stacking layers is pointless, because a chain of linear operations collapses into a single linear operation. Ten layers of pure multiplication and addition is mathematically identical to one layer. The non-linearity is what makes depth mean anything.

Definition · Layer

A group of neurons that all receive the same inputs and produce outputs in parallel. Networks stack layers so that later ones operate on features discovered by earlier ones. "Deep learning" simply means many stacked layers.

Why does depth help? A rough intuition from image recognition, where it was first made visible: the first layer learns edges, the second learns corners and textures out of edges, the third learns shapes out of corners, and later layers learn objects. Nobody programmed that hierarchy. It emerged because the architecture allows composition and the training data rewarded it.

Chapter 4Generalisation, and the thing that ruins everything

A model that perfectly reproduces its training data is not necessarily useful. If you have 500 houses and enough parameters, the model can memorise every one and get zero loss, then fail completely on house 501. This is overfitting, and it is the central failure mode in all of machine learning.

Definition · Overfitting

When a model learns the noise and accidents of the training data rather than the underlying pattern. It scores brilliantly on data it has seen and poorly on data it has not.

The standard defence is to split your data. You train on one portion and evaluate on another the model has never seen. The gap between training performance and held-out performance tells you whether you learned a pattern or memorised a list.

Why this matters later

This idea, that performing well on the examples you were tested on does not prove you will perform well in general, is the same idea that motivates this entire project. An AI agent that passes its test suite has done well on data it was measured against. Whether it behaves correctly on a slightly reworded version of the same request is a different question, and one that almost nobody measures. Hold onto this: it recurs in Chapter 17 as the eval gap, and again in Chapter 19 as metamorphic testing.

Part II · Language models

Chapter 5Tokens: how text becomes numbers

Neural networks do arithmetic on numbers. Text is not numbers. Something has to bridge that, and the bridge is tokenisation.

A naive approach would give each word a number. This breaks immediately: languages have unbounded vocabularies, people invent words, and misspellings would be unrepresentable. The other extreme, one number per character, makes sequences enormously long and forces the model to rediscover spelling from scratch.

Modern systems use subword tokenisation, typically an algorithm called Byte Pair Encoding. Common words become single tokens. Rare words fragment into pieces. The word "unbelievable" might become un, bel, iev, able. A useful rule of thumb for English is that one token is roughly four characters, or about 0.75 words.

Definition · Token

The atomic unit a language model reads and writes. Not a word, not a character, but a chunk of text somewhere between the two. Pricing, context limits and speed are all measured in tokens.

This matters practically. When this project spent $11.02, it was billed on 3.67 million input tokens and 373,000 output tokens. Input and output are priced differently: Claude Haiku 4.5 costs $1.00 per million input tokens and $5.00 per million output. Output is five times dearer because generating requires a full forward pass through the network for every single token, while input can be processed in parallel.

Chapter 6The prediction task

Here is the whole thing, and it is stranger than most explanations admit. A language model does exactly one job: given a sequence of tokens, produce a probability distribution over which token comes next.

Not "answer the question". Not "be helpful". Predict the next token. Everything else is a consequence.

Given "The capital of France is", the model outputs a probability for every token in its vocabulary. " Paris" gets a high probability. " Berlin" gets a low one. " purple" gets a very low one. The system picks one, appends it, and feeds the whole longer sequence back in to predict the token after that. This is called autoregressive generation.

Plain English

A language model is an extremely sophisticated autocomplete. Everything it appears to do, reasoning, translating, writing code, follows from being very good at guessing what comes next given everything so far.

Why does that produce apparent intelligence? Because to predict the next token well across the entire internet, you must implicitly model an enormous amount. To finish "The murderer turned out to be the" in a detective story, you need to have tracked the plot. To finish "the result of 17 × 24 is", you need arithmetic. Next-token prediction is a task whose full solution requires understanding a great deal, and scaling the model and data pushes it toward that solution.

The consequence people miss

Because the model only ever predicts plausible continuations, it has no separate mechanism for "is this true". A fluent, well-formed, completely false statement is a perfectly good next-token prediction. This is the mechanical origin of hallucination, and it is why an agent's confident summary of what it did is not evidence of what it did. That single fact is the seed of this entire project.

Chapter 7The transformer

The architecture behind every current language model was introduced in 2017 by Vaswani and colleagues at Google, in a paper titled "Attention Is All You Need". Its central mechanism is self-attention.

The problem attention solves: when processing a word, which other words in the text matter? In "The trophy did not fit in the suitcase because it was too large", what does "it" refer to? Change "large" to "small" and the referent flips from trophy to suitcase. Any system that processes words in isolation, or only with a fixed nearby window, cannot handle this.

How attention works

For each token, the model computes three vectors, which are just lists of numbers:

  • a query: what this token is looking for
  • a key: what this token offers to others
  • a value: the content this token contributes

To process a given token, the model compares its query against every other token's key. High similarity means high relevance. Those similarities become weights, the weights are normalised to sum to one, and the token's new representation is the weighted average of all the values. A token that is highly relevant contributes a lot; an irrelevant one contributes almost nothing.

A helpful analogy: a query is a search box, keys are the titles of every document, values are the documents themselves, and the output is a blend of documents weighted by how well their titles matched your search.

Two more details make it work. Multi-head attention runs several of these in parallel, so one head can track grammatical subject while another tracks topic and another tracks long-range references. And because attention has no inherent notion of order, positional encoding adds information about where each token sits in the sequence.

Definition · Context window

The maximum number of tokens the model can attend over at once. Claude models now reach 1,000,000 tokens; Haiku 4.5 handles 200,000. Attention cost grows roughly with the square of the sequence length, which is why long contexts are expensive and why very long ones needed algorithmic work to become feasible.

Chapter 8Pretraining, and everything after it

Building a usable model happens in stages, and confusing them causes most misconceptions about what these systems are.

Stage one: pretraining

The model is shown an enormous corpus of text and trained to predict the next token. Nothing else. No labels, no instructions, no human feedback. This is where nearly all of the compute is spent and where nearly all of the capability comes from.

The result is a model that completes text. It is not helpful, because helpfulness was never the objective. Ask a purely pretrained model a question and it might respond with a plausible list of similar questions, because that is what often follows a question on the internet.

Stage two: supervised fine-tuning

Humans write examples of good behaviour, thousands of question-and-answer pairs demonstrating the desired style. The model continues training on these. It now answers rather than continuing. Capability barely changes; behaviour changes a lot.

Stage three: reinforcement learning from human feedback

Humans are shown several model responses and asked which is better. Those comparisons train a separate reward model that predicts human preference. The language model is then optimised to score well under that reward model. This is RLHF, and it is what makes models feel cooperative and appropriately cautious.

A subtlety with real consequences

RLHF optimises for what human raters prefer, which is not identical to what is true or complete. Raters tend to prefer confident, well-organised, helpful-sounding answers. A model can therefore be trained toward sounding right at the margin.

You will see this exact effect in Chapter 38. An agent skipped two required checks, one of which errored, and produced a beautifully structured summary with headings and tick marks explaining its decision. The summary did not mention the skipped checks. It was not lying. It was producing the kind of output that gets rated highly.

Chapter 9Sampling, temperature, and why the same question gives different answers

The model outputs a probability distribution, not a single token. Something must choose. That choosing is sampling, and it is the direct source of the non-determinism this whole project measures.

  • Greedy decoding always takes the highest-probability token. Deterministic, and prone to repetitive, flat text.
  • Temperature sampling picks randomly in proportion to probability, with a dial. Temperature below 1 sharpens the distribution toward the likeliest tokens. Above 1 flattens it, making unlikely tokens more available. At 0 it collapses to greedy.
  • Top-p (nucleus) sampling restricts the choice to the smallest set of tokens whose probabilities sum to p, then samples within that set. This adapts: where the model is confident the set is tiny, where it is unsure the set is wide.
Plain English

Temperature is a creativity dial that is really a randomness dial. Low means predictable and repetitive. High means varied and more likely to go wrong. There is no setting that means "correct".

Even temperature 0 is not reproducible

People assume temperature 0 gives identical outputs every time. In practice it usually does not, for a mundane reason: floating-point arithmetic on GPUs is not associative, so (a+b)+c can differ in the last bits from a+(b+c). Batching, hardware and kernel scheduling all vary between runs. When two probabilities are nearly tied, that last-bit difference flips which token wins, and one different token changes everything after it.

This is why you cannot get reproducibility by turning a knob. You get it, if at all, by taking control flow away from the model. That is the hypothesis this project tests.

One practical wrinkle worth knowing, because this project hit it. The current Claude models, Opus 5 and Sonnet 5 and the 4.7-and-later family, removed sampling parameters entirely. Sending temperature returns an error. Older models including Haiku 4.5 still accept it. When the study's sampling perturbation crashed on every run, that was the cause, and the crashed runs were being silently reported as though the agent had skipped every step.

Chapter 10What a language model fundamentally cannot do

Understanding the limits precisely is what separates people who deploy these systems well from people who are surprised by them.

It has no memory

The API is stateless. Each request is independent. A conversation feels continuous only because the client resends the entire history every time. There is no "it" that remembers you between calls. This is why long conversations cost more with each turn: you are paying to resend everything.

It cannot act

A model emits text. It cannot read a file, query a database, or move money. When an agent "calls a tool", the model has produced a structured request and your code performed the action. This distinction is the entire architecture of Part III, and it is the mechanism the deterministic-orchestration argument relies on.

It has no access to truth

There is no fact-checking module. The model produces likely text. Likelihood and truth correlate because the training data was mostly true, but they are not the same thing and nothing in the architecture enforces the difference.

It cannot reliably report on itself

Ask a model why it did something and you get a plausible explanation, generated the same way as any other text. It is not introspection; it is a story about a process the model has no privileged view of.

This is the whole project in one line

An agent's own account of what it did is generated text, not a log. If you want to know what an agent did, you must record what it did. That recording is called a trajectory, and comparing trajectories is what Plumbline exists to do.
