Why nothing catches it

Output evals grade the answer, and the answer was right. Trace viewers show you one run. Neither can detect a check that did not happen, because the disposition comes out identical either way. The agent even wrote the omission into its own audit log, gave a reason that reads as sensible, and closed the case.

Why one test is not enough

Auditors may test a conventional automated control once and rely on it for the period, because a deterministic system behaves the same way every time, so one observation generalises. A language model does not, and one clean test bounds almost nothing:

n  ≥  ln(1 − α) / ln(1 − p_tol)        α = 95%

  1 clean run   ....  true failure rate could still be 95.0%
 30 clean runs  ....  could still be 9.5%
299 clean runs  ....  under 1.0%

Reaching 99% confidence that an agent-operated control runs takes 299 consecutive clean executions. Nobody is running 299.

The method

Hold the invoice fixed and vary only what cannot change the decision: reword the request, append irrelevant text, add tools it does not need, raise the sampling temperature, drop one tool call. Then check whether every control still executed. This is metamorphic testing, and it needs no oracle: the relation between the variants is the oracle.

A result I withdrew. My first headline said the coded baseline lost badly under that tool fault, at p = 0.0029. Before publishing it I checked whether the baseline was fair. It was not: no retry logic, which no finance integration ships. I added the retry, re-ran the identical protocol, and the effect vanished (p = 0.46). Written the way anyone would ship it, the deterministic system was flawless. Both studies are in the repository.

What comes out

Not a dashboard. A test of controls, in the form a control owner and their auditor already work from: deviation rates against tolerable rates, sample sizes derived from confidence rather than copied from a table, exact binomial bounds, and every deviation traced to the run, the transaction and the condition that produced it. The command exits non-zero on a deficiency, so a pipeline can block the release.
